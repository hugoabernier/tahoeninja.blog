Building a Multi-Step Form with SPFx and React Hooks

Hugo Bernier · May 28, 2025 · 8 min read
SharePoint React SPFx

Multi-step forms are one of the most requested UI patterns in SharePoint development. Done well, they reduce cognitive load and improve completion rates dramatically.

[ Featured image ]

When building enterprise SharePoint solutions, multi-step forms often feel like the right call — but the implementation details can make or break the user experience. Let's walk through a clean approach using SPFx and React's useState hook.

Why Multi-Step Forms?

The psychology is simple: presenting 20 fields at once is intimidating. Breaking them into logical groups — identity, preferences, confirmation — reduces perceived complexity and keeps users moving forward.

Accessibility note: Always ensure step indicators are accessible to screen readers. Use aria-current="step" and announce step changes with a live region.

Setting Up the State

We'll manage all form state in a single object at the top level. This makes it trivial to pass data between steps and to submit everything at once.

MultiStepForm.tsx · TypeScript 
interface FormData {
  // Step 1 — Identity
  displayName: string;
  email: string;
  department: string;

  // Step 2 — Preferences
  notifyByEmail: boolean;
  notifyByTeams: boolean;
  frequency: 'daily' | 'weekly' | 'monthly';
}

const MultiStepForm = () => {
  const [step, setStep] = useState(0);
  const [data, setData] = useState<Partial<FormData>>({});

  const updateField = <K extends keyof FormData>(
    key: K,
    value: FormData[K]
  ) => setData(prev => ({ ...prev, [key]: value }));

  return (
    <StepContainer
      currentStep={step}
      onNext={() => setStep(s => s + 1)}
      onBack={() => setStep(s => s - 1)}
    >
      {step === 0 && <IdentityStep data={data} onChange={updateField} />}
      {step === 1 && <PreferencesStep data={data} onChange={updateField} />}
      {step === 2 && <ConfirmationStep data={data} />}
    </StepContainer>
  );
};

The key insight here is using a generic update function. TypeScript ensures we can't accidentally assign a string to a boolean field, giving us compile-time safety without any extra ceremony.

The Step Container

The container is deliberately thin — it handles navigation logic and progress display, nothing else. Business logic stays in the individual step components where it belongs.
