Building a Multi-Step Form with SPFx and React Hooks

Multi-step forms reduce cognitive load and improve completion rates. Here's a clean, type-safe approach using modern React patterns in a SharePoint Framework web part.

🥷
Hugo Bernier
May 28, 2025 · 8 min read

When building enterprise SharePoint solutions, multi-step forms are one of the most-requested UI patterns — and one of the trickiest to get right. Let's build one properly, with full TypeScript safety and accessible step navigation.

Modeling the State

The first decision is how to store form state. A single object at the top level keeps things predictable and makes the final submission straightforward. Use a generic update helper to get compile-time key safety.

◆ MultiStepForm.tsx 
1interface FormData {
2  displayName: string;
3  email: string;
4  notifyByEmail: boolean;
5  frequency: 'daily' | 'weekly' | 'monthly';
6}
7
8const MultiStepForm: React.FC = () => {
9  const [step, setStep] = useState(0);
10  const [data, setData] = useState<Partial<FormData>>({});
11
12  const update = <K extends keyof FormData>(k: K, v: FormData[K]) =>
13    setData(prev => ({ ...prev, [k]: v }));
14
15  return <Wizard step={step} onNext={() => setStep(s => s+1)} />;
16};
💡

The Partial<FormData> initial state lets TypeScript know that fields may not be filled in yet — avoiding runtime errors when accessing data before the user reaches that step.

Step Validation Strategy

Validate on step transition, not on submit. This surfaces errors early without overwhelming the user. Here's how the step config maps validators to each step:

Step Fields Validator Status
0 — Identity displayName, email validateIdentity() Implemented
1 — Preferences notifyByEmail, frequency validatePrefs() Implemented
2 — Confirm — — Review only

Keeping validators pure functions makes them trivial to unit-test in isolation — no component mounting required.
